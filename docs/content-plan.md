# 东方隐侠：研究与内容运行计划

## 定位与读者

研究 AI 如何安全地进入真实工作。面向使用 AI 的研发人员和负责 AI 接入的安全人员，从实际任务理解能力、权限、执行与审计。

千里的技术发展主线：亲手构建工作流 → 建立评估 → 验证控制措施 → 获取真实使用反馈。官网积累这些过程的证据，公众号、CSDN、FreeBuf 和 B站承担不同形态的传播。

## 这轮页面调整

- 首页：当前重点研究 → 问题入口 → 原创研究 → 外部精选 → 自动资讯 → 作者。首页不把资讯热度当作研究质量，不设置未经统计的阅读量或影响力数字。
- 课题页：可用阅读入口和阅读路径前置，结论与待验证事项可直接定位，保留已有道法术器、平台链接、资产和修订记录。
- 精选资料：独立搜索与类型、关联课题筛选。保留原作者、发布时间、收录日期和推荐理由。
- 作者：主页、文章署名与团队页相互关联。保留既有团队形象，不增加未经证实的客户、奖项、行业地位或已完成实验。

## 六个双周研究包

以下均为计划，不代表已经完成。

| 周次 | 问题 | 最小新增成果 | 传播形式 |
| --- | --- | --- | --- |
| 1—2 | Hook 能控制到哪里？ | 在测试环境记录正常调用、拒绝与异常退出，标记版本和样本指纹 | 公众号问题拆解 + CSDN 实验步骤 |
| 3—4 | 编码 Agent 能读哪些文件？ | 合成凭据、固定任务与权限配置对照；禁止使用真实凭据 | B站屏幕演示 + FreeBuf 边界分析 |
| 5—6 | MCP 授权与本地执行有什么不同？ | 一条 HTTP、一条 stdio 测试链路及其身份、权限图 | 原理文章 + 官网规范索引修订 |
| 7—8 | 一次确认究竟批准了什么？ | 比较确认对象、执行参数与最终副作用的记录 | 公众号应用判断 + 技术实测 |
| 9—10 | 日志能证明控制生效吗？ | 关联授权、工具调用、执行结果和目标系统的测试记录 | 检查清单 + 演示 |
| 11—12 | 控制措施是否妨碍任务完成？ | 固定任务前后对比，收集两位使用者的测试反馈 | 完整研究、局限、下一阶段计划 |

每周预算 6—8 小时。一个月完成两个研究包，从其中一个制作视频；视频用实验录屏。紧急热点占用同一预算，替换一个短评，不叠加工作量。

## 选题和证据

相关性、真实问题强度、自有增量、可执行性各 0—2 分；总分至少 6，且自有增量不为 0，才安排独立发布。仅有新闻价值的条目进入资讯归档。

每条原创核心结论注明属于官方声明、第三方报告、本站静态分析、本站动态复现或工程建议。记录环境、版本、日期、前提和局限。没有动态验证不写“实测有效”；没有实证不把控制措施说成无法绕过。

每篇外部资料保留来源和自己的摘要。链接引用不称完整转载，翻译或完整转载另行核实授权。失效和版本过期按实际核查结果修订，不自动刷新“已核验”日期。

## 一次研究，多平台交付

- 官网：完整研究、实验材料、适用范围、关联来源与修订记录。
- 公众号：一个真实问题、一项关键判断、一组可执行建议。
- CSDN：具体工具与版本、环境、步骤、代码、错误与排查。
- FreeBuf：威胁模型、触发条件、证据、影响、防护和局限。
- B站：先演示现象，再解释机制、控制前后差异和未解决问题。

每个平台内容自身完整。原文回链遵守平台规则，发布后将真实地址填回课题的 links 或 videos。标题须与实际证据一致，严禁把计划中的实验写成已完成。

## 维护入口

- 首页重点、阅读路线、精选来源：`_data/editorial.yml`。只引用已经存在的课题、文章和资料 slug。
- 外部资料：`_resources/*.md`。原文链接使用 `external_url`，不能使用 Jekyll 保留的 `url` 字段。
- 研究与阅读路径：`_topics/*.md`。维持现有 status，阶段性结题不等于永久有效。
- 文章主稿：仍使用现有编辑器与发布脚本，不直接修改生成的 `_articles` 正文。
- UI：`assets/editorial.css` 管新版视觉；原有长文排版仍由 `assets/style.css` 提供。

## 月度复盘

发布第 7 天和第 30 天记录同平台、同形态的阅读或播放、关注增长、具体问题和外部引用；官网记录专题访问与来源（有数据再填，未接入统计不推算）。另外记录实验复现、资料采用和分享邀请。

第 4 周检查实验能否重复；第 8 周检查有无外部反馈；第 12 周决定保留的栏目及下阶段试点。不通过检查时缩小问题或重访用户，不增加发布频率补偿。
