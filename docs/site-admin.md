# 官网工作台

启动：`python3 scripts/edit_article.py --no-open --port 8971`。
打开 http://127.0.0.1:8971/ 。旧文章编辑器保留在 `/editor`。
停止：`python3 scripts/edit_article.py --stop --port 8971`。

环境需要 Python 3.9+、PyYAML、Pillow、Git 和现有 Jekyll。缺少 Python 依赖时执行
`python3 -m pip install -r scripts/requirements-admin.txt`。部署状态查询另需已登录的 GitHub CLI。

## 内容入口

- 首页：首屏文字、侠客图片、羽化程度、高度、板块顺序和显隐、重点研究和推荐入口。
- 研究课题：元信息、道法术器、成果入口、维护记录和 Markdown 正文。
- 原创文章：原有注册文章继续编辑外部母稿；新文章直接保存在 `_articles`，可用工作台编辑。
- 精选资料：来源、推荐理由、关联课题和链接。
- 兵器谱、关于我们：结构化条目、介绍和联系方式。
- 导航与页脚：七个栏目排序、显隐、标题、介绍及页脚快捷入口。
- 栏目页面：页面元信息与 Liquid/Markdown 源码，适合进一步调整结构。
- 素材库：图片选择、上传和路径复制。上传文件会进入本地工作区，发布时需一并选择。
- 资讯与留言：资讯仍由独立仓库提供，留言仍由 GitHub Discussions 管理；提供对应管理入口。

## 保存与发布

正文上方提供格式工具栏：段落标题、加粗、斜体、删除线、引用、列表、行内代码、代码块、链接、表格和分隔线。选中文字后操作，保存格式仍为 Markdown，官网预览自动更新。支持 Ctrl/Cmd+B、I、K；图片仍可粘贴或从素材库插入。

协作交稿统一使用原生草稿：需要人工润色的官网稿与渠道稿，都应能在「原创文章」直接打开和编辑。渠道稿独立保存并在标题注明渠道，不自动写入官网。继续改稿先读取后台最新内容，遵守版本冲突检查。完整约定见 [创作与传播流程](editorial-workflow.md)。

1. 保存草稿：保存在 `~/.local/share/eastsword-admin/<站点标识>/drafts`，不改官网文件。
2. 预览：在隔离副本中生成当前内容，构建真实 Jekyll 页面。其他草稿不自动混入当前预览。
   原创文章打开后自动预览，编辑停顿约 600 毫秒后重新构建；构建时间另计。自动预览使用未保存内容，不自动保存或写入官网。正文支持直接粘贴剪贴板图片，上传后插入 Markdown 图片链接；图片文件进入本地素材库，发布文章时需一并选择。
3. 准备发布：先构建检查，再保存到本地源文件，随后自动进入发布中心；此时尚未提交、推送或上线。失败会恢复本次涉及的文件，保留草稿。文章已经写入本地时，该按钮直接进入发布中心。
4. 发布中心：默认选中全部待发布文件，可取消不需要的文件。点击“发布到官网”查看清单，再“确认发布”；后台自动检查、构建、提交并推送。检查失败时停止并显示原因，未选文件不会加入新提交。

检测到母稿或草稿被其他窗口修改时，必须重新加载并合并；不会直接覆盖外部修改。
发布中心会明确列出尚未提交的文章，并保留最近一次检查/发布的结果和错误。服务重启时未完成的任务显示“结果未知”，不会自动重试推送。推送完成仍须查看 GitHub Pages 的部署结果。
写入前的内容备份位于同一状态目录的 `history`，当前需人工读取恢复。
已有暂存内容会阻止后台发布；推送失败时本地提交保留，可以重试。
推送会发送当前分支的所有未推送提交，发布中心会显示已有未推送提交。

工作台仅监听本机回环地址，不应通过反向代理直接暴露到公网。
本地官网 4018 若采用静态预览目录，需要另外构建刷新；工作台内的预览按钮会自行构建。

## 验证

`python3 -m unittest discover -s scripts -p test_site_admin.py -v`

覆盖草稿隔离、版本冲突、失败恢复以及所选文件的发布检查与 Git 暂存区隔离。
