# 既有课题如何持续完善

文章创作、官网发布、渠道分发和 SEO/GEO 复盘，统一按 [小文章创作与传播流程](editorial-workflow.md) 执行。本文仅说明成果成熟后如何归入课题，不要求采用道法术器的文章结构。

先在「原创文章」写清一个具体问题，文章成熟后再分析是否能补充既有研究课题。新增文章不要求同步修改课题，也不要求预先绑定 `topic`。

当前 GitSpawn 文章独立放在原创文章中，不绑定课题。`ai-agent-governance` 课题页保留原状态、结论和维护记录，不新增本文入口。

文章完成后，如决定将成果沉淀到课题，再按以下顺序维护：

1. 原创文章填写 `topic: ai-agent-governance`，正文开头链接课题，结尾链接相关综合长文。
2. 在课题的「术」中加入成果入口，文章使用 `publication: true` 与 `type: 原创`；一般说明、官方文档不需要原创或转载标签。
3. 在阅读路径说明谁适合先读这篇；成果入口简要区分综合长文与专题短文。
4. 只有出现有证据的新判断，才补充「当前研究结论」；未验证的适用性放入「尚待验证」，注明证据方式和版本。
5. 更新维护日期与变更记录，说明新增了什么，不把局部案例改写成全局结论。

是否调整课题状态取决于实际研究进展，不因新增一篇文章自动变更。

GitSpawn 文章保存在工作台「原创文章」的原生草稿 `articles/gitspawn-agent-startup` 中，可直接编辑；不使用外部母稿注册机制。既有课题位于 `_topics/ai-agent-governance.md`，工作台「研究课题」可编辑。

GitSpawn 文章当前为工作台状态目录中的隔离草稿，尚未写入官网文件；本轮不发布课题更新。未来纳入课题时，确认文章已经上线或与课题入口同时发布。内部 `docs` 文档不进入公开站点。
