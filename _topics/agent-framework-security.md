    text: 智能体被沙箱约束，同时又能调用决定沙箱模式的接口，权限模型就成了一个环。评估任何 Agent 框架都先问：控制面对被控主体是否可达？可达的话，它有没有独立于被控主体的身份验证？

  - title: 审批机制要防「改规则」，不只是「破规则」
    text: 「会话级策略 + 逐次审批」的结构有一个空档，判定条件是「命令权限是否超出会话权限」，而攻击改的是会话权限本身。修改策略的操作本身需要审批，放行动作要能证明是人做的。

    type: 原创
    platform: 本课题
  - title: 提示注入现在有了完整的落点

## 核心问题

Agent 框架是智能体的运行时。它用沙箱约束行为，用审批约束权限，用控制面承接指令，用配置面管理凭据，用扩展层接入工具。本课题研究的就是这套约束体系自身：它是否经得起被控主体的检验，是否经得起不可信内容的检验，声明与实现之间有没有落差。

研究视角偏攻击侧审计，防御设计作为评估对象一并研究。与企业侧管控课题（员工都在用 AI Agent，企业安全该怎么管）互为攻防两面，与 MCP 供应链课题（扩展层投毒）在能力扩展维度交叉，本课题聚焦框架自身的信任边界。

第一个完整案例是 CVE-2026-82533（DeepSeek Harness 沙箱逃逸），后续的框架审计、机制评估与案例复盘在这个页面持续累加。

## 研究方向

- **沙箱与执行隔离**：隔离声明与实现的一致性、跨平台 profile 差异、读写网络进程各维度的覆盖
- **审批与权限模型**：会话级策略的防改写、审批队列的身份绑定、放行动作的归因
- **控制面与配置面认证**：本地接口的信任假设、请求头的角色、令牌与凭据的设计
- **能力扩展层**：工具、Skill、MCP 接入时的信任迁移，扩展层漏洞的框架化
- **披露与修复**：披露时间线、维护者回应、通报质量、修复方案与分发
