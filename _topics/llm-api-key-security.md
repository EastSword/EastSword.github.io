## 核心问题

LiteLLM 的 CVE-2026-42208（预认证 SQL 注入）2026 年 5 月进 CISA KEV：公告公开不到 36 小时即被在野利用，攻击者用 17 个 UNION 载荷直奔存上游 Key 的三张表，全程没碰别的数据。CSA 的定性是"单个实例失陷等同于整个云账户失陷"。这不是孤例，是产业链：Sysdig 实测受害账单每天 46,000 美元起，旗舰模型场景最坏评估超 10 万美元/天，Pillar Security 归因的 Bizarre Bazaar 战役 40 天 35,000+ 攻击会话。国内全国级数据：电信云堤测绘显示暴露量占 87.17% 的 Ollama 恶意事件占比反而不高，只占 11.46% 的 LiteLLM 承担了 47.03%。扫的是整个暴露面，打的是钱袋子；追踪两周，补认证的暴露目标只有约 1%。Wiz 测得 90% 的云环境在跑自托管 AI 软件，FOFA 实测（2026-08-30）持上游 Key 的网关类系统公网 23.3 万台（中国境内约 7.65 万）、无认证 Ollama 端点 111.6 万个。

口令不是关键，公网暴露才是；藏得深也不属于防御，因为攻击者读的是开源系统的源码，比运维更清楚 Key 在哪。API Key 的安全模型和密码不是一回事：配置一次长期有效、明文躺在配置文件和进程内存里、调用时没有任何行为特征可供画像。密码失窃还要过第二因子和异地登录风控，Key 失窃等于直接持有一个完整的合法身份，账单记在被偷方头上。

## 覆盖内容

- **双口径攻击面测量**：13 个框架精确指纹与宽口径分开统计（Flowise 精确 39 台 / 宽口径 46,994 台，差三个数量级），持 Key 网关、Agent 平台、开发环境三梯队分类，每个数字带口径说明，不报营销数字
- **八条提取路径**：面板正面进入（默认口令 / 渠道越权 / SQLi）、认证绕过加命令注入、Agent 框架盲注、进程内存提凭据、供应链投毒、配置枚举、资源劫持、钓鱼窃取。第七条不偷凭证，诱导 Agent 替你调用（直接索取成功率 0.67%，诱导代用 92.00%）；第八条不打系统直接打人（假 Claude Code 安装页战役：32 个 Google Sites、88 个域名、隐藏分隔符载荷）
- **MCP 服务器泄露层**：8,000+ MCP 服务器暴露公网，人工验证的 119 台全部无需认证；实测链路无认证枚举 → SSRF 打 AWS 元数据 → file:// 读进程环境变量，四步拿到活的云凭据；OpenClaw 第三方客户端 150 万 API Key 泄露；slopsquatting 抢注 AI 幻觉出的包名（14 个包 12 万次下载，平均存活 11 天）
- **四台国内系统实证**：未授权直进的行业 AI 教学管理平台、弱口令进入且主密钥可见的大模型管理后台、「账户已禁用」却照登的检测 API 用户中心、登录页返回「用户不存在」的 AI 视频监控系统。同一结论的四种形态：工程安全基本功是成片缺课
- **一手工具实证**：自建审计脚本对 422 个公网 Flowise 实例做形态判定，四个 CVE 路径全量核对、凭据库匿名可读实例的取证口径；Ollama 从目录穿越读宿主机文件到凭据狩猎的完整链路
- **受害案例与损失三层结构**：国内两份完整复盘（凌晨一小时烧掉 5000 元 / 单日异常消耗 3.2 万美元），账单损失、服务中断、处置人力三层拆解。后两层从不出现在任何泄露统计里
- **防御八条与实施顺序**：公网无认证按已失陷处理、版本压过 KEV 基线、检测走运行时、提示词和知识库按生产配置管、密钥治理四件事、敏感调用任务级授权……每条写落地卡点与推进顺序，不给正确但不可执行的清单
